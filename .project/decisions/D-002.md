# Description
GitHub Models must not be added back to the digest as a provider family. GitHub fully retired GitHub Models on 2026-07-30 according to GitHub's own documentation and changelog. The endpoint did not go away with the service: models.github.ai still answers HTTP 200 with the plain text body OK for /, /catalog/models, /inference/models, and a POST to /inference/chat/completions -- with a valid token, an invalid one, or none at all. A status-code health check therefore falsely passes even though no model is served. Evidence: probe runs 42363318770 and 42364043037; the second printed models=0 | status=200 | verdict=no_answer. F-001 added the family in commit 71cf488 and it was removed in commit 6c806d6, and a comment in scripts/llm_providers.py records the prohibition.

# Why
Recorded so the family is not re-proposed on the strength of an HTTP 200. The retired service still answers 200 with a body of OK, which is exactly the signal that makes a dead provider look healthy; a future proposal has to answer this evidence, not merely re-run the endpoint and see 200.

# Acceptance Criteria
- The retired family is not re-added to the digest.
- Any provider health check treats a 200 whose body is plain OK, with no model list and no completion, as a failure rather than a pass.
- If GitHub ever restores a real service, the change of plan is a new decision record referencing this one rather than an edit that erases the original reasoning.
