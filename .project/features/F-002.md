# Description
A second Gemini project key exists with its own separate free quota and answers 200 in probe run 42263580979 (row `gemini-key2`). Make it a first-class rung of the digest walk, wired the same way the primary Gemini key is, through `config/opencode-cli.json`, `config/opencode.json`, `llm_providers.py`, `model_selector.py` and the three workflows. When the second key is absent the rung is skipped cleanly and nothing else changes.

Scope: those five wiring points only. Out of scope: replacing the primary key, adding a third key, and any change to prompts or model choice.

# Why
Two keys on the same family with separate free quotas double the available walk capacity when the first key reaches its free-quota ceiling, with no change to prompts or model behaviour. It is the cheapest additional rung, but it is not an independent family, so it complements rather than replaces a non-Gemini provider.

# Acceptance Criteria
- The walk selects the second key when the first is exhausted or failing, and the run records which key served the response.
- All five wiring points carry the key consistently, so the CLI path and the workflow path cannot disagree.
- When the key is absent the ladder skips it with no error, no retry loop and no blank card.
- Probe output continues to show separate `gemini` and `gemini-key2` rows.
- No key value is written into the repository, a workflow file or a ledger record; only the variable name is referenced.
