# Description
The digest reaches chat completions through the billed opencode pool and the Gemini project keys, while the HTTP providers (Groq, OpenRouter, Mistral) serve summaries and repair only and cannot run the tool-using digest walk. Add GitHub Models (models.github.ai) as a further independent family, authenticated by the token the workflow already carries, and make it selectable by the walk through `model_selector.py`, not only by the summary/repair lane. A probe row must prove it answers.

Scope: a provider adapter in `llm_providers.py`, a walk ladder rung in `model_selector.py`, the workflow wiring, and the probe row. Out of scope: changes to news collection, and retiring or reordering the existing ladder rungs.

# Why
GitHub Models is free, adds no new repository secret, and is a different model family from Gemini, so it covers both a Gemini-side outage and a Gemini key-exhaustion event. Owner's standing goal, verbatim: "add as many backups as possible so it will work for years without you needing to work from time to time". Model-id retirement on a roughly 6-12 month cycle is the dominant long-term failure mode, which makes a non-Gemini family worth more than another key on a family that already exists.

# Acceptance Criteria
- The walk ladder in `model_selector.py` can select GitHub Models; the provider is not limited to the summary/repair lane.
- Authentication uses only the token the workflow run already has; no new repository secret is introduced.
- `llm_providers.py` gains an adapter whose failure path returns the same honest status shape as the existing providers.
- A probe run prints a GitHub Models row with the responding model id, alongside the existing gemini, gemini-key2, groq, openrouter and mistral rows.
- When the token is absent or Models is unavailable, the run continues on the remaining providers and the digest still ships.
- A blank card stays structurally impossible on every path, whether or not this provider is available.
