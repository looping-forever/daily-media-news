# Description
Model ids are currently pinned. Google retires ids on roughly a 6-12 month cycle, so a pinned id becomes the dominant long-term failure: the provider is up, the key is valid, and the edition still breaks because the named model no longer exists. Resolve each provider rung's model from that provider's catalogue at run time, using the pinned id only as a preferred hint, so a retirement self-heals on the next run. When discovery finds nothing usable, report it honestly with the probe's existing `no_chat_model` / `model_rejected` wording rather than falling silently through to a weaker path.

Scope: catalogue lookup per provider, deterministic selection, substitution logging, and honest empty-catalogue reporting. Out of scope: changing which families exist, and changing prompts.

# Why
This is the failure mode most likely to break the digest in a year without anyone touching the code, and the owner's goal is explicitly to avoid periodic manual repair. The reporting vocabulary for an empty catalogue already exists in the probe, so the honest failure path does not need inventing.

# Acceptance Criteria
- Every provider rung resolves its model id from the provider's catalogue at run time; the pinned id is a preference, not a requirement.
- A retired id produces a successful run on the discovered replacement, with the substitution logged once.
- When discovery returns nothing usable the probe prints `no_chat_model`, or `model_rejected` when candidates exist but all fail, and the digest still ships.
- Selection is deterministic for a given catalogue, so two runs on the same day choose the same model.
- Any cached choice expires, so a discovery result can never become a silent long-term pin.
